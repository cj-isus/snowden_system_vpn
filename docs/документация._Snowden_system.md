## 1. Обзор проекта

**Unkillable VPN** — десктопное приложение для Windows, которое:

- Подключается к личному VPS через VLESS+TLS (с настоящим Let's Encrypt сертификатом)
- Автоматически поддерживает туннель при обрывах (Circuit Breaker + авто-reload)
- Переключается на Cloudflare WARP при падении VPS (бесплатный fallback)
- Маршрутизирует российский трафик напрямую (split-tunneling, 30K CIDR)
- Показывает реалтайм-логи и диагностику в UI
- Управляет системным прокси Windows автоматически

**Цель:** «нажал кнопку — и работает безотказно при любых блокировках»

### Краткие характеристики

| Параметр | Значение |
|---|---|
| Платформа | Windows 10/11 x64 |
| Фреймворк | Wails v2 (Go backend + Vue3 frontend) |
| Ядро VPN | sing-box-lx v1.14.0-lx.2 (embedded) |
| Размер бинарника | ~34 МБ |
| Протокол | VLESS+TLS (Let's Encrypt сертификат) |
| Fallback | Cloudflare WARP (WireGuard, бесплатно) |
| Цена | 0 ₽ (nip.io + Let's Encrypt + WARP бесплатно) |

## 2. Технологический стек и обоснование

### Backend: Go + Wails v2

**Почему не Electron / Tauri / Flutter:**

| Фреймворк | Почему нет |
|---|---|
| **Electron** | ~100 МБ, высокое потребление RAM, избыточен |
| **Tauri (Rust)** | Rust ≠ Go; sing-box написан на Go, линковка Go↔Rust через FFI нетривиальна |
| **Flutter Desktop** | 40-80 МБ; для embedded sing-box нужен dart:ffi + gomobile — сложный toolchain |

**Почему Wails (Go):**
- Backend на Go = прямой импорт sing-box как библиотеки (`github.com/sagernet/sing-box`)
- Web-фронтенд (Vue3/React/Svelte) — привычный UI-стек
- ~10-20 МБ бинарник
- Go создан для network-задач

### Ядро: sing-box-lx (форк sing-box)

**Почему не upstream sing-box:**
- Upstream sing-box **не содержит AmneziaWG** (issue #4045 — открыт)
- sing-box-lx — thin fork от Leadaxe, rebases на каждый upstream tag
- Добавляет: AWG 2.0, XHTTP, MASQUE, observability (CommandClient)
- Module path сохранён (`github.com/sagernet/sing-box`) — identity preserved

**Почему не mihomo (Clash.Meta):**
- mihomo лучше для подписок и rule-routing
- sing-box-lx лучше для самохостинга и свежих протоколов
- Выбрали sing-box-lx т.к. нужен embedded в Go-процесс

### Frontend: Vue3 + TypeScript + Vite

- Лёгкий, реактивный, быстрая сборка
- TypeScript-биндинги генерируются Wails автоматически
- Размер бандла: ~65 КБ (gzip: ~26 КБ)

## 5. Ядро: sing-box-lx embedded

### Почему embedded, а не subprocess

**Факт (sing-box issue #3806):** на Windows graceful shutdown sing-box через `CTRL_BREAK` 
не работает без консоли. Флаг `CREATE_NO_WINDOW` убирает консоль, и `GenerateConsoleCtrlEvent` 
не доставляется.

**Решение:** sing-box встроен в Go-процесс через `box.Box`:
```go
instance, err := box.New(box.Options{
    Context:           ctx,
    Options:           options,
    PlatformLogWriter: e.platformWriter(), // ← ключ: стриминг логов
})
instance.Start()   // запускает sing-box ВНУТРИ процесса
instance.Close()   // graceful shutdown (не ОС-сигнал!)
```

**Преимущества:**
- Graceful Start/Close работает на Windows без консоли
- Нет subprocess-ов, нет PID-управления
- Логи стримятся через Go-каналы (PlatformWriter), не через REST/WS
- Изоляция: panic в sing-box не роняет GUI (восстанавливается через recover)

### Регистрация протоколов

Upstream `include.Context()` тянет **все** протоколы, включая `protocol/naive` → 
`cronet-go/all` (Chromium cronet бинарники для tvOS/iOS, ~30 файлов, не качаются 
через RU-restricted proxies).

**Решение:** собственный `boxContext()` в `registry.go`, регистрирующий 
только нужные протоколы:

```go
func boxContext(parent context.Context) context.Context {
    return box.Context(parent, inbounds(), outbounds(), endpoints(),
        dnsTransports(), services(), certificateProviders())
}
```

Зарегистрированные протоколы:
- **inbounds:** tun, mixed, socks, http, shadowsocks
- **outbounds:** vless, vmess, trojan, shadowsocks, shadowtls, hysteria, hysteria2, masque
- **endpoints:** wireguard (с AWG через build tag)
- **groups:** selector, urltest

Так как `protocol/naive` **не импортируется**, весь naive→cronet subgraph **никогда не 
попадает** в дерево импортов. Подтверждено: `cronet` в go.mod = 0, в go.sum = 0, 
в дереве компиляции = 0.

## 6. Конфигурация sing-box 1.14

### Миграция с 1.11→1.14 (что изменилось)

При переходе с upstream 1.13.14 на sing-box-lx 1.14.0 потребовалась миграция формата:

| Было (1.11) | Стало (1.14) | Причина |
|---|---|---|
| `"address": "https://1.1.1.1/dns-query"` | `"type": "https", "server": "1.1.1.1", "path": "/dns-query"` | legacy DNS format removed в 1.14 |
| `sniff: true` на inbound | `{ "action": "sniff" }` в route.rules | legacy inbound fields removed в 1.13 |
| outbound `"type": "dns"` | `{ "action": "hijack-dns", "inbound": "mixed-in", "protocol": "dns" }` | dns outbound deprecated в 1.13 |
| `experimental.clash_api` | Убран (баг в lx 1.14: `invalid argument`) | Clash API не работает в lx 1.14 |

### Текущий конфиг (`template-vps-reality.json`)

```json
{
  "log": { "level": "info", "timestamp": true },
  "dns": {
    "servers": [
      { "type": "https", "tag": "cloudflare", "server": "1.1.1.1", 
        "path": "/dns-query", "detour": "auto" },
      { "type": "local", "tag": "local", "detour": "direct" }
    ],
    "rules": [{ "outbound": "any", "server": "local" }],
    "strategy": "ipv4_only"
  },
  "inbounds": [{
    "type": "mixed", "tag": "mixed-in",
    "listen": "127.0.0.1", "listen_port": 20808
  }],
  "endpoints": [{
    "type": "wireguard", "tag": "warp-fallback",
    "address": ["172.16.0.2/32"],
    "private_key": "<WARP key>",
    "peers": [{ "address": "162.159.192.1", "port": 4500, ... }]
  }],
  "outbounds": [
    { "type": "urltest", "tag": "auto",
      "outbounds": ["proxy", "warp-fallback", "direct"],
      "interval": "1m", "tolerance": 100 },
    { "type": "vless", "tag": "proxy",
      "server": "192.109.206.234", "server_port": 443,
      "uuid": "...", "tls": { "server_name": "snowden-system.192-109-206-234.nip.io" } },
    { "type": "direct", "tag": "direct" },
    { "type": "block", "tag": "block" }
  ],
  "route": {
    "rules": [
      { "action": "sniff" },
      { "action": "hijack-dns", "inbound": "mixed-in", "protocol": "dns" },
      { "rule_set": ["ru-cidr"], "action": "direct" },
      { "ip_is_private": true, "action": "direct" }
    ],
    "final": "auto",
    "default_domain_resolver": "local",
    "auto_detect_interface": true
  }
}
```

### Ключевые решения

1. **`server` = числовой IP** (192.109.206.234), а не домен — чтобы избежать DNS-loop 
   (sing-box не может резолвить домен outbound-сервера через detour, который 
   зависит от этого же outbound)

2. **`server_name` = домен** (snowden-system.duckdns.org) — для TLS-проверки сертификата

3. **`flow` убран** — `xtls-rprx-vision` вызывал `TLS handshake: context deadline exceeded`. 
   Провайдер начал резать Vision-flow TLS-handshake. Без flow — работает.

4. **`utls` убран** — uTLS fingerprint=chrome также вызывал блокировки. 
   Чистый TLS работает. (uTLS поддерживается в бинарнике через `with_utls` tag, 
   но не используется в конфиге)

5. **`insecure` убран** — сервер использует настоящий Let's Encrypt сертификат, 
   клиент проверяет его валидность

## 7. Split-tunneling (раздельное туннелирование)

### Что делает

Российские IP-адреса идут **напрямую** (без VPN), заблокированные — **через VPN**. 
Это даёт:
- Быстрый доступ к Яндекс, ВК, Сбербанк, Госуслуги (без overhead VPN)
- Доступ к YouTube, Telegram, Discord через VPS

### Реализация

Используется `rule_set` типа `local` с файлом `ru-cidr.json`:

```json
{
  "rule_set": [{
    "type": "local",
    "tag": "ru-cidr",
    "format": "source",
    "path": "ru-cidr.json"
  }]
}
```

Файл `ru-cidr.json` генерируется из `ru-cidr.lst` (30 228 CIDR из Telegram-экспорта):
```json
{
  "version": 3,
  "rules": [{ "ip_cidr": ["2.63.0.0/17", "2.63.128.0/18", ...] }]
}
```

### Код (`app.go: injectSplitTunnel`)

При `LoadConfigFile` конфиг автоматически обогащается:
1. Читается `ru-cidr.lst` (comma-separated CIDR)
2. Конвертируется в sing-box source rule-set JSON
3. Записывается `ru-cidr.json` рядом с exe
4. В route.rules добавляется `{ "rule_set": ["ru-cidr"], "action": "direct" }`

## 8. Системный прокси Windows

### Проблема

sing-box 1.14 убрал `set_system_proxy` inbound field (deprecated). Браузеры 
не подхватывают прокси автоматически.

### Решение

Прямое управление Windows registry через Win32 API (`advapi32.dll`):

```go
func setSystemProxy(host string) error {
    // HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings
    // ProxyEnable = 1
    // ProxyServer = "127.0.0.1:20808"
    // + InternetSetOption(INTERNET_OPTION_SETTINGS_CHANGED) для уведомления WinINet
}
```

- **При ВКЛ:** `setSystemProxy("127.0.0.1:20808")` — браузеры подхватывают мгновенно
- **При ВЫКЛ:** `clearSystemProxy()` — `ProxyEnable = 0`
- **При аварийном выходе:** `OnShutdown` в main.go очищает прокси

### Важно

Прокси выставляется **только если движок реально запущен** (проверка `st.Connected`):
```go
if st.Connected {
    setSystemProxy("127.0.0.1:20808")
}
```
Иначе браузер укажет на мёртвый прокси → «Прокси-сервер отказывается принимать соединения».

## 9. AdaptiveEngine + Circuit Breaker

### Назначение

Автоматическое поддержание туннеля: детект обрывов, классификация причин, 
восстановление (reload / fallback).

### Circuit Breaker (3-state)

```
        3 неудачи подряд                    cooldown истёк
   CLOSED ──────────────────────► OPEN ─────────────────► HALF_OPEN
     ▲                                │                        │
     │ 2 успеха подряд                │ 1 неудача               │
     └────────────────────────────────┴────────────────────────┘
```

| Состояние | Что происходит | Интервал probe |
|---|---|---|
| **CLOSED** (HEALTHY) | Нормальная работа, probe каждые 30с | 30с |
| **OPEN** (FAILED) | Engine.Reload (переустановка VLESS), cooldown растёт экспоненциально | 10с→60с |
| **HALF_OPEN** (RECOVERING) | Пробные запросы, 2 успеха → CLOSED | немедленно |

### Пороги

```go
failThreshold:   3    // неудач в CLOSED для перехода в OPEN
halfOpenProbes:  2    // успехов в HALF_OPEN для возврата в CLOSED
cooldownStart:   10с  // стартовый cooldown
cooldownMax:     60с  // потолок (экспоненциальный рост: 10→20→40→60)
```

### Действия при OPEN

1. `Engine.Reload(config)` — переустановка VLESS-соединения
2. Если reload не помог → ждём urltest auto-failover (VPS→WARP→direct)
3. Специальный случай: `CatNetworkDown` — не reload'им (бесполезно, ждём интернет)

## 10. Error Classifier (классификация ошибок)

### Назначение

Парсит логи sing-box в реальном времени и классифицирует ошибки для 
circuit breaker и UI.

### Категории

| Категория | Паттерн в логе | Объяснение для UI |
|---|---|---|
| `network_down` | proxy connection refused on 127.0.0.1 | «Нет интернета» |
| `server_down` | `dial tcp ... i/o timeout`, `connection refused` | «Сервер не отвечает» |
| `dns_failure` | `lookup failed`, `no such host` | «Ошибка DNS» |
| `tls_failure` | `TLS handshake ... timeout/failed/eof` | «TLS заблокирован» |
| `server_blocked` | `REALITY: invalid`, `connection reset` на outbound | «ТСПУ заблокировал» |
| `whitelist_mode` | все заблокированные упали + рунет работает | «Белые списки (БС)» |
| `degraded` | работает, но медленно (latency > 2× baseline) | «Медленный туннель» |
| `healthy` | нет ошибок | «Всё работает» |

### Реализация

Только `[error]` и `[warn]` уровни логов классифицируются — это устраняет 
ложные срабатывания на info/debug/trace строках (проверено: без фильтра 
`dns:` в debug-логах вызывало ложное `dns_failure`).

Классификатор получает логи через `PlatformWriter` → `Engine.classifier`:
```
sing-box → WriteMessage(level, msg)
    ↓
platformLogWriter.WriteMessage
    ├── handler.OnLog(line)       → UI (engine:log event)
    └── classifier.OnLog(line)    → классификация → circuit breaker
```

### Для UI

Метод `Diagnostics()` возвращает:
```json
{
  "state": "HEALTHY",
  "category": "healthy",
  "explanation": "Всё работает нормально",
  "lastError": "",
  "failCount": 0,
  "okCount": 0
}
```

## 11. Graceful Degradation (VPS → WARP → Direct)

### Принцип

Если VPS падает, sing-box `urltest` автоматически переключает на следующий:

```
urltest[auto]:
  proxy (VLESS→192.109.206.234)   ← основной (NL, AMS)
  warp-fallback (WireGuard→CF)    ← резерв 1 (Cloudflare, бесплатно)
  direct                          ← резерв 2 (напрямую, интернет без VPN)
```

- `interval: 1m` — проверка каждую минуту
- `tolerance: 100` — гистерезис 100мс (анти-дрожание)
- Если VPS оживает — автоматически переключается обратно

### Почему `direct` в конце

Если **все** серверы упали, `direct` обеспечивает минимальный интернет 
(без VPN). Лучше чем «нет ничего».

## 12. WARP+AWG генератор (бесплатный fallback)

### Принцип

Cloudflare WARP — бесплатный VPN через Cloudflare. Регистрация через API:

```
1. Генерируем X25519 пару (Go crypto)
2. POST https://api.cloudflareclient.com/v0a2158/reg
   Body: { "key": "<public_key_b64>", "install_id": "", ... }
3. Получаем: device_id, client_id, peer_public_key, endpoint
```

### WireGuard outbound (endpoint)

```json
{
  "type": "wireguard",
  "tag": "warp-fallback",
  "address": ["172.16.0.2/32"],
  "private_key": "<сгенерированный>",
  "peers": [{
    "address": "162.159.192.1",
    "port": 4500,
    "public_key": "bmXOC+F1FxEMF9dyiK2H5/1SUtzH0JuVo51h2wPfgyo=",
    "allowed_ips": ["0.0.0.0/0", "::/0"]
  }]
}
```

### AWG (AmneziaWG) статус

AWG параметры (`jc`, `jmin`, `jmax`, `h1`-`h4`) **не работают** в 
sing-box-lx 1.14.0-lx.2 — ошибка `IPC error -22: invalid UAPI device key: jc`. 
Используется чистый WireGuard (без AWG обфускации). AWG ожидается в lx.3.

## 13. Управление логами (PlatformWriter)

### Архитектура стриминга

```
sing-box (box.Box)
   ↓ log.PlatformWriter interface
platformLogWriter (engine.go)
   ├── handler.OnLog(line) → Wails runtime.EventsEmit("engine:log")
   │                          → App.vue EventsOn("engine:log")
   │                          → logs.value.push(line)
   └── classifier.OnLog(line) → ErrorClassifier → категория
```

**Без Clash API, без REST, без polling** — нативный Go-интерфейс.

### Реализация

sing-box вызывает `WriteMessage(level, message)` для каждой лог-строки. 
Мы форматируем её как `[level] message` и отправляем:
1. В UI через Wails event
2. В ErrorClassifier для классификации

`PlatformLogWriter` также активирует `needObservable = true` внутри `box.New()`, 
что инициализирует `trafficManager` (для tracking соединений).

## 14. Автозапуск с Windows

### Реализация

Через registry `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`:

```go
func setAutostartRegistry(enabled bool) error {
    k, _ := registry.OpenKey(registry.CURRENT_USER, runKey, registry.SET_VALUE|registry.QUERY_VALUE)
    if enabled {
        exePath, _ := os.Executable()
        return k.SetStringValue("UnkillableVPN", `"exePath"`)
    }
    return k.DeleteValue("UnkillableVPN")
}
```

- **HKCU** — не требует прав админа (per-user)
- Методы `SetAutostart(true/false)` и `IsAutostartEnabled()` доступны из UI

## 15. Build tags (сборка)

### Проблема

Wails **игнорирует** поле `tags` в `wails.json` (проверено эмпирически). 
Бинарник собирался без `with_utls`, и Reality падал с `uTLS is not included`.

### Решение

**Всегда передавать `-tags` через CLI:**
```bash
wails build -skipbindings -s -tags "with_awg,with_wireguard,with_utls,with_gvisor"
```

### Теги

| Tag | Что включает |
|---|---|
| `with_awg` | AmneziaWG 2.0 (протокол; параметры пока не работают в lx.2) |
| `with_wireguard` | WireGuard endpoint (transport/wireguard/device.go) |
| `with_utls` | uTLS (fingerprint для TLS; обязателен для Reality) |
| `with_gvisor` | gVisor userspace TCP/IP stack (для WireGuard в userspace) |

### wails.json

```json
{
  "tags": "with_awg,with_wireguard,with_utls,with_gvisor"
}
```

Формат — **запятая-разделённый** (не пробелы).

### Проверка бинарника

```python
with open('unkillable-vpn.exe','rb') as f: data=f.read(50_000_000)
t=data.decode('latin-1','ignore')
print('uTLS is not included (д.б. 0):', t.count('uTLS is not included'))
# 0 = with_utls скомпилирован правильно
# 1 = stub скомпилирован (tags не применены)
```
